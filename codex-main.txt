KAERTEI Project — Persistent Context (for future AI sessions)

Last Updated: 2025-09-07

- Platform: Jetson Nano 4GB
- OS: Ubuntu 20.04 (Focal)
- Target ROS 2: Foxy Fitzroy
- Constraint: No Docker (bare‑metal only)
- Goal: Minimal scripts and docs; keep only essential setup/build/run

Hardware Links (Serial)
- Pixhawk FCU: `/dev/ttyACM0` @ `115200` (MAVROS FCU link)
- RTK Receiver: `/dev/ttyUSB0` @ `115200` (RTCM/NMEA into Jetson)
  - Bridge: `rtk_serial_bridge` forwards serial RTCM → `/mavros/gps_rtk/send_rtcm`

Mission Context
- Mission controller: 12‑checkpoint FSM in `kaertei_drone/kaertei_drone/mission/checkpoint_mission_mavros.py`.
- Use MAVROS for arming/modes/takeoff; use GPS waypoint monitoring via `gps_waypoint_monitor.py`.
- Prefer unified vision, but be mindful of Jetson Nano 4GB performance.

Topik/Interface Target (to keep consistent)
- Vision: publish `/vision/detection` (geometry_msgs/Point) and `/vision/aligned` (std_msgs/Bool).
- LiDAR: adapt Range to Float32 for `/lidar/front/distance` if needed.
- Magnet: choose ONE command topic and keep consistent (prefer `/magnet/command`).

Build/Run Baseline (Foxy)
- Source: `/opt/ros/foxy/setup.bash` then build with colcon.
- Build: `./kaertei_drone/scripts/build_kaertei.sh`
- Run: `./kaertei_drone/scripts/run_kaertei.sh [debug|auto]`.

Open Items to remember

- YOLOv8 may be too heavy on Nano 4GB; consider tiny models/TensorRT if needed. Update chosen model here.
